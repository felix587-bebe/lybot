# LyBot — поиск и обработка музыки (YouTube Music)

Работает на OnyxGram (`https://dev-angel-7553.dev`), поиск и получение треков — через YouTube Music (`ytmusicapi` + `yt-dlp`).

## Что было почищено / исправлено

**Баг с инлайном (красный «!», "Неизвестен", "0:00 / -:--")**
В `handlers/music.py` для текстового поиска и для расшаренных треков без кэша бот
отдавал в инлайн `InlineQueryResultAudio` с сырой CDN-ссылкой YouTube, полученной через
`yt-dlp`. Серверы Telegram сами идут по этой ссылке, чтобы прочитать метаданные для
превью — а такие ссылки привязаны к IP/сессии, с которой их доставал `yt-dlp`, и живут
недолго. С другого IP (сервера Telegram) они не отдаются → ровно та картинка, что была
на скриншоте.

Исправлено: инлайн теперь отдаёт **только** уже закэшированные треки (есть `file_id`,
полученный после того как трек хоть раз скачали и отправили через самого бота —
`InlineQueryResultCachedAudio`, это надёжно). Если трека ещё нет в кэше — инлайн вместо
битого аудио вежливо подсказывает открыть бота и найти трек там один раз, после чего он
появится и в инлайне.

**Мусор убран:**
- `get_yt_cookies.py` — локальный одноразовый скрипт выгрузки cookies из Яндекс.Браузера, для прода не нужен.
- `test_yt.py` — ручной CLI-тест, не часть бота.
- `downloads/` с реальными mp3 — временные файлы, в репозитории быть не должны (сам код их не создаёт туда — это был мусор от старых локальных запусков).
- `musicbot.db` — локальная БД с данными, на Render создастся с нуля через `init_db()`.
- `.git/` — не переносил, в истории секретов не было, но проще начать репозиторий заново.
- `YANDEX_MUSIC_TOKEN` в `.env`/`config.py` — не использовался нигде в коде (реально всё работает через YouTube Music, не Яндекс.Музыку), удалён.
- `requirements.txt` был на 70+ пакетов (Pyrogram, Telethon, TgCrypto, pandas, numpy, uvicorn, starlette, stem/PySocks и т.д.) — ни один не импортируется в коде. Оставил только то, что реально используется: `aiogram`, `aiohttp`, `aiosqlite`, `python-dotenv`, `ytmusicapi`, `yt-dlp`, `yt-dlp-ejs`, `imageio-ffmpeg` (кстати последний вообще отсутствовал в старом файле, хотя импортируется в коде — реальный баг, который проявился бы при чистой установке).
- `yandex.py` → переименован в `ytmusic.py` — файл называл YouTube Music «yandex» (наследие от более ранней версии на Яндекс.Музыке), это путало. Содержимое не трогал, только импорты поправил.

**⚠️ В `.env`, который был в архиве, — боевые `BOT_TOKEN` и `YANDEX_MUSIC_TOKEN`.**
В git они не попадали (проверил историю), но раз токены прошли через загрузку сюда —
советую перевыпустить `BOT_TOKEN`. `YANDEX_MUSIC_TOKEN` всё равно удалён за ненадобностью,
но если он активно использовался где-то ещё — тоже стоит проверить.

## Подготовка к Render

Бесплатный план Render не даёт Background Worker — только Web Service, а тот обязан
слушать `$PORT`, иначе health-check считает деплой нездоровым. У поллинг-бота своего HTTP
нет, поэтому в `main.py` добавлена:
1. Лёгкая aiohttp-заглушка на `$PORT`, отдающая `200 OK` — только чтобы Render был доволен.
2. Самопинг раз в 10 минут на `RENDER_EXTERNAL_URL` (Render сам прописывает эту переменную
   на Web Service) — бесплатные сервисы Render засыпают через ~15 минут без HTTP-трафика,
   это не даёт заснуть. На лимиты плана и подвисания по другим причинам это не влияет.

`render.yaml` обновлён (`YANDEX_MUSIC_TOKEN` убран).

### Деплой
1. Залей содержимое этой папки в свой git-репозиторий (GitHub/GitLab).
2. На Render: New → Blueprint → выбери репозиторий (подхватит `render.yaml`) **или**
   New → Web Service вручную с `buildCommand: pip install -r requirements.txt` и
   `startCommand: python main.py`.
3. В Environment пропиши `BOT_TOKEN` (секретный, не коммить).
4. Деплой. `RENDER_EXTERNAL_URL` и `PORT` Render подставит сам.

### Локальный запуск
```
cp .env.example .env   # вписать BOT_TOKEN
pip install -r requirements.txt
python main.py
```
